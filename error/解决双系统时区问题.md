### 🕒 双系统时间不同步问题完整总结

>   记录 Windows + Linux 双系统下切换后时间相差 8 小时的工程级解决方案与完整操作步骤。

#### 问题现象

>   切换系统后时间出现明显偏差。

表现：

-   Windows 时间不对

#### 问题根本原因

>   双系统对 RTC（硬件时钟）的默认理解不一致。

核心矛盾：

-   Linux 默认认为 RTC 为 UTC
-   Windows 默认认为 RTC 为本地时间

结果：

-   Linux 写入 UTC
-   Windows 按本地时间读取
-   → 产生 8 小时时差

#### 正确工程级解决方案

>   统一 RTC 标准为 UTC，并让 Windows 读取 UTC（Linux 推荐模式）。

统一标准：

-   让 RTC 使用 UTC
-   让 Windows 适配 UTC

#### 完整操作步骤

>   先在 Linux 统一 RTC，再在 Windows 适配并同步时间。

① Linux 端设置 RTC 为 UTC

执行：

```
sudo timedatectl set-local-rtc 0
```

确认：

```
timedatectl
```

应看到：

```
RTC in local TZ: no
System clock synchronized: yes
NTP service: active
```

说明：

-   RTC 已改为 UTC
-   Linux 自动 NTP 校时

② Windows 端改为读取 UTC

>   必须使用管理员 CMD。

打开方式：

-   Win + S → 搜索 `cmd`
-   右键 → 以管理员身份运行

执行：

```
reg add "HKLM\SYSTEM\CurrentControlSet\Control\TimeZoneInformation" /v RealTimeIsUniversal /t REG_DWORD /d 1 /f
```

成功提示：

```
操作成功完成。
```

③ 重启 Windows

>   必须重启才能生效。

④ Windows 手动同步一次时间

路径：

-   设置 → 时间和语言 → 日期和时间 → 立即同步

作用：

-   触发 NTP
-   刷新系统时间

#### 最终正确状态

>   双系统均由 NTP 校时，RTC 统一为 UTC。

Linux：

```
timedatectl
```

应为：

```
RTC in local TZ: no
System clock synchronized: yes
NTP service: active
```

Windows：

```
w32tm /query /status
```

应显示已同步。

#### 完成后的结构

>   RTC 统一后形成稳定闭环。

结构示意：

```
RTC = UTC
         ↑
Linux ←→ NTP
         ↓
Windows ←→ NTP
```

#### 以后是否还要操作

>   一次性永久方案，除非系统环境重置。

结论：

-   不需要每次手动同步
-   不需要再看 warning

需要重做的情况：

-   重装 Windows
-   清 CMOS
-   刷 BIOS

#### 工程级理解

>   通过注册表键让 Windows 将 RTC 视为 UTC。

注册表键：

```
RealTimeIsUniversal = 1
```

含义：

-   Windows 不再把 RTC 当成本地时间
-   改为 UTC，与 Linux 一致

#### 常见错误总结

1.  普通 CMD 执行注册表 → 拒绝访问
2.  使用 `^` 换行符 → 进入 `More?`
3.  忘记“立即同步” → 时间未刷新

#### 核心一句话总结

>   双系统时间问题的唯一干净方案：RTC 用 UTC，Windows 适配 Linux。
