### 个人笔记风格总结

>   用于长期复习、整理知识、写学习记录或技术文档，强调逻辑清晰、可操作性和统一风格。

------

#### 一、文档结构要求

##### **总体格式**

1.  全文使用 Markdown。
2.  一级主题使用 `###`。
3.  二级主题使用 `####`。
4.  三级主题使用 `#####`。
5.  子模块内容使用 **粗体标题** 开头，例如：**基本原理**、**操作步骤**、**示例代码**。
6.  模块开头可用 `>` 写一句简介或说明
7.  自动加入一行以 `>` 开头的**简要说明**，作为该主题和标题的简介
8.  子标题下如果没有更小一级的标题或者序号，尽量不要使用分割线。

##### **命令和代码**

1.  所有命令尽量整合到一个终端块展示，而不是拆分过多子标题。
2.  避免使用数字符号（如“⑥”）或彩色 emoji。
3.  所有 C++/ROS2 代码必须使用代码块，并附中文解释。
4.  命令使用独立代码块，并附中文说明。

------

#### 二、内容编排

1.  按知识点分主题整理，逻辑清晰。
2.  步骤使用数字序号：
    1.  第一步……
    2.  第二步……
3.  每节可适当加入总结、注意事项、对比说明。

------

#### 三、场景化内容

1.  常见场景（如 Git 多分支协作、ROS2 节点生命周期、MoveIt 任务流程、上位机/下位机通信、多线程+定时器、工程结构重构等）分小节说明。
2.  每个场景描述结构：
    1.  背景说明
    2.  主要问题
    3.  操作流程（数字步骤）
    4.  示例代码
    5.  关键注意事项

------

#### 四、报错与排查

**报错 / 注意事项**

>   报错描述
>    原因：说明导致问题的技术原因
>    解决方案：

```
# 给出实际可执行的命令、补丁或代码示例
```

------

#### 五、参考资料

-   可选，列出官方文档或参考链接。
-   标题使用：#### 参考 / 链接

------

### 提示词（Prompt）

>   请按照以下风格整理我的笔记、文档或教程：

-   使用 Markdown，主题层级为 `###`、`####`、`#####`。

-   子模块以 **粗体标题** 开头。

-   模块开头可用 `>` 写简介说明

-   在每个小标题下必须加入以 “> ” 开头的简要描述作为说明

-   逻辑清晰、按主题分类整理内容。

-   命令尽量整合在一个终端块展示，不拆分为太多子标题。

-   子标题不使用数字符号（如“⑥”）或彩色 emoji。

-   步骤使用数字序号。

-   报错独立成小节，包含描述、原因和解决方案代码块。

-   可选参考资料小节使用 `#### 参考 / 链接`。

-   子标题下如果没有更小一级的标题或者序号，尽量不要使用分割线

-   默认情况下，只做风格和排版调整（Markdown 层级、代码块、中文说明、清晰条理等）。

-   不主动删除、合并或精简原笔记内容，也不添加额外解释或扩展内容，除非你明确要求“丰富”。

-   保持原始意思和步骤完整，只优化阅读体验。
